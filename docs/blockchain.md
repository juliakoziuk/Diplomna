# Публічний блокчейн: як записувати корені в Polygon

За замовчуванням AnchorProof працює з **демонстраційним реєстром** (`network: "mock"`): корені партій
лежать у БД сервера. Цей документ описує, як перейти на справжній блокчейн (Polygon).

## Як це влаштовано

```
документи → партія (дерево Меркла) → корінь → контракт MerkleAnchor (Polygon) → квитанція
```

- Контракт [`contracts/contracts/MerkleAnchor.sol`](../contracts/contracts/MerkleAnchor.sol) зберігає корені
  за номерами версій (епох). Записувати може лише **індексатор**, це службовий гаманець сервера.
- Читати може будь-хто. Тому браузер перевіряє квитанцію, **читаючи контракт сам** через публічний RPC,
  і не покладається на наш сервер.
- Квитанція містить `network` і `contract`. Верифікатор звіряє адресу контракту з офіційною (`GET /v1/chain`):
  без цього будь-хто міг би розгорнути свій контракт і наповнити його підробленими коренями.
- Без налаштувань сервер лишається на демонстраційному реєстрі. Старі квитанції (`mock`) і далі перевіряються.

Записується лише **документний потік** (епохи Anchor API). Версії індексу для пошуку (`verifiable-search`)
поки лишаються в імітації: вони створюються при кожному старті сервера, і записувати їх у мережу тут недоречно.

## Службовий гаманець

Це окремий гаманець застосунку, а не ваш особистий. Генерується одним скриптом, приватний ключ
записується в `backend/.env.local` (у `.gitignore`) і **не друкується**:

```bash
cd contracts
npm install
npm run wallet:new      # покаже лише публічну адресу
```

## Тестова мережа Polygon Amoy (безкоштовно)

1. Візьміть тестові POL для адреси з попереднього кроку: <https://faucet.polygon.technology> (оберіть Polygon Amoy).
2. Розгорніть контракт:

   ```bash
   cd contracts
   npm run deploy:amoy
   ```

   Скрипт записує `ANCHOR_CHAIN_ID` і `ANCHOR_CONTRACT_DOCUMENTS` у `backend/.env.local`.
3. Застосуйте міграції (`npm run migrate` у `backend/`) і перезапустіть бекенд. У логах має з'явитись
   `on-chain anchoring ON: polygon-amoy …`.
4. Зафіксуйте документ у кабінеті: у квитанції буде `network: polygon-amoy`, адреса контракту й посилання
   на транзакцію в Polygonscan.

Свій RPC (Alchemy, Infura…) можна вказати в `ANCHOR_CHAIN_RPC_URL`; за замовчуванням береться публічний.

## Змінні середовища (`backend/.env.local`)

| Змінна | Призначення |
|---|---|
| `ANCHOR_PRIVATE_KEY` | ключ службового гаманця (створює `npm run wallet:new`) |
| `ANCHOR_CHAIN_ID` | `80002` (Amoy) або `137` (Polygon mainnet) |
| `ANCHOR_CONTRACT_DOCUMENTS` | адреса контракту (записує `npm run deploy:*`) |
| `ANCHOR_CHAIN_RPC_URL` | необов'язково: свій RPC замість публічного |

Усі три `ANCHOR_*` (ключ, мережа, контракт) мають бути задані, інакше використовується імітація.

## Локальна перевірка без інтернету

```bash
cd contracts
npm test                # 6 тестів контракту на вбудованій мережі Hardhat
npm run node            # окремий термінал: локальна нода (chain 31337)
WRITE_ENV=0 npm run deploy:local   # гаманець поповнюється автоматично; адреса виводиться
```

Потім запустіть бекенд зі змінними `ANCHOR_CHAIN_ID=31337`, `ANCHOR_CONTRACT_DOCUMENTS=<адреса>`,
`ANCHOR_CHAIN_RPC_URL=http://127.0.0.1:8545`.

## Що важливо знати

- **Amoy — тестова мережа:** публічна й безкоштовна, але не вічна і не має юридичної ваги. Для реального
  використання потрібен Polygon PoS (mainnet, `npm run deploy:polygon`, справжні POL). Не переходьте на нього,
  поки тестовий прогін не пройде чисто.
- **Номери епох окремі для кожного реєстру.** Демо-реєстр і кожен контракт лічать від 1, тому квитанція завжди
  вказує свій `network`.
- **Збій запису.** Якщо транзакція не пройшла (немає коштів на газ, RPC недоступний), документи лишаються
  `pending`, і наступна епоха спробує ще раз. Причина видна в логах бекенда.
- **Безпека ключа.** Ключ службового гаманця зберігайте лише в `.env.local` або секретах хостингу. Для
  mainnet краще менеджер ключів (наприклад, AWS KMS). Контракт має `setIndexer` для заміни ключа.
- **Компілятор.** Hardhat компілює пакетом `solc` з npm (`solc@0.8.24`), а не завантажує нативний
  компілятор: це відтворювано й працює без доступу до `binaries.soliditylang.org`.
